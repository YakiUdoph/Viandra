# Repository agent instructions

These instructions apply to the entire repository.

1. Read `PRD.md`, `ARCHITECTURE.md`, `DESIGN.md`, `RULES.md`, `TASKS.md`, and `PROGRESS.md` before changing application code.
2. Keep the product name Viandra and preserve the mission and boundaries in `PRD.md`.
3. Work in focused batches. Preserve the selected lightweight stack unless a verified blocker requires change.
4. Do not spend SERV credits, deploy, publish, post socially, or submit to the competition without explicit user authorization.
5. Do not expose or log credentials or full user instructions. Do not persist user content unless requirements change explicitly.
6. Treat user input and model output as untrusted. Validate structure and exact evidence quotations; render as text, never unsafe HTML.
7. Do not fabricate successful analysis, test results, official requirements, deployment, compliance, or provenance.
8. Use deterministic mocks and fixtures for tests. Live SERV checks must be separately authorized and reported.
9. Prefer targeted tests and one production build after implementation; avoid unnecessary dependency or research loops.
10. Update `TASKS.md` and `PROGRESS.md` whenever implementation or verification status materially changes.
11. Keep README’s first heading exactly `# How to test`.
12. If an unavailable rule source (including the Serial Hackathon Winner Playbook) becomes available, preserve it and reconcile without inventing retroactive guidance.
